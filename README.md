# Telegram чат · GREEN-API

Тестовое задание на React + TypeScript. Выбран Telegram — разрешённая в условии альтернатива MAX. Интерфейс простого мессенджера в тёмной теме, Tailwind CSS.

## Локальный запуск

Нужны Node.js 24 LTS и npm. После клонирования репозитория выполните:

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173).

```sh
npm run build
npm run preview
npm run lint
npm test
```

Сборка находится в `dist`. Для статического хостинга: команда сборки `npm run build`, каталог публикации `dist`. Сервер и база данных не требуются.

### Netlify

Импортируйте репозиторий `quester16/green-api`, выберите ветку `main`. Файл `netlify.toml` задаёт сборку `npm run build`, каталог `dist` и Node.js 24. Файл `public/_redirects` автоматически копируется Vite в `dist` и направляет клиентские маршруты на `index.html`, чтобы прямое открытие или обновление страницы не возвращало 404. Токен GREEN-API не нужно добавлять в переменные Netlify: пользователь вводит его в интерфейсе.

## Подготовка GREEN-API

1. Создайте инстанс **Telegram** в https://console.green-api.com/ и авторизуйте свой Telegram через кабинет.
2. В настройках инстанса включите `incomingWebhook` (уведомления о входящих сообщениях), оставьте `webhookUrl` пустым. После сохранения дайте настройкам примениться.
3. Скопируйте `idInstance`, `apiTokenInstance` и `apiUrl` из кабинета. Токен вводится в интерфейсе, не в исходниках. В разделе «Адрес API из кабинета» можно изменить хост; по умолчанию указан `https://4100.api.green-api.com`.
4. Для уведомлений об ошибках доставки включите уведомления о статусах исходящих сообщений (`outgoingWebhook`).
5. Используйте одну вкладку приложения на инстанс: другая вкладка или интеграция может забирать события из общей очереди.

## Основной сценарий

1. Введите ID и токен, нажмите «Подключиться». Приложение проверяет состояние инстанса.
2. Введите международный номер собеседника, нажмите «Открыть чат». Номер нормализуется, `checkAccount` возвращает настоящий `chatId`. Номер должен быть доступен для поиска в Telegram.
3. Введите текст, нажмите кнопку отправки или Enter. После принятия API сообщение появляется справа, поле очищается. Успешный запрос означает принятие в очередь, не прочтение собеседником.
4. Ответьте со второго аккаунта Telegram. Текст автоматически появится слева.
5. Другой чат можно открыть по другому номеру. Сообщения хранятся раздельно по `chatId` в текущей сессии.
6. «Отключиться» останавливает получение, очищает переписку и токен формы.

## Проверка перед сдачей

- Неверные данные подключения и недоступный номер показывают ошибку.
- Пустой текст не отправляется; во время запроса повторная отправка заблокирована.
- Два последовательных сообщения отправляются; ответ появляется в том же чате.
- Повторное уведомление не создаёт дубль, событие другого чата не попадает в открытую переписку.
- При ошибке отправки текст остаётся. Автоматического повтора отправки нет: при таймауте сначала проверьте Telegram, чтобы не отправить дубль.
- При отключении запрос получения отменяется, старые сообщения не переходят к новому аккаунту.

Автотесты покрывают нормализацию номера, разбор уведомлений, сопоставление чатов, сохранение исходящих и защиту от дублей. Реальный обмен нужно проверить на своём авторизованном инстансе и втором аккаунте.

## Ограничения

Только текстовые личные сообщения (включая текст с URL). Нет файлов, группового интерфейса, базы данных и загрузки старой истории. После обновления страницы сообщения и подключение сбрасываются. Полученные события подтверждаются `deleteNotification` и повторно из очереди не загружаются. Входящие неподдерживаемые события тоже подтверждаются.

Developer разрешает ограниченное число чатов; ошибка 466 означает ограничение тарифа. Используется единый `chatId`, чтобы телефон и ID не расходовали квоту как разные адреса. `checkAccount` может не найти пользователя из-за приватности номера. Квоты и авторизация сервиса не могут быть исправлены кодом приложения.

Учётные данные хранятся только в памяти вкладки, но видны владельцу браузера в сетевых запросах — это клиентское тестовое приложение. Не публикуйте токен в репозитории, видео или скриншотах; если старый токен ранее был опубликован, замените его в кабинете.

## Структура

- `Chat.tsx` — состояние сессии, выбранный чат, последовательное получение, интерфейс.
- `ConnectInstances.tsx` — формы подключения и открытия чата.
- `api.ts` — запросы GREEN-API и понятные ошибки.
- `messageUtils.ts`, `types.ts` — модель сообщений, преобразование и дедупликация.
- `Message.tsx` — отображение сообщения.
